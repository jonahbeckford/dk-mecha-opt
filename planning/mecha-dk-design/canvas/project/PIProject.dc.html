Passed as: each item is given to dk0 run-function after --, grouped by kind, then by whether the mecha may change it or only read it. So a function rule can tell what it may write, and a read-only item stays read-only. The name is made from the item's name; change it if your function rule expects another.
What the experiment is given, after --The words form the function rule's request document:
dk0 run-function [MODULE@VERSION] -d [results]/ --
  repo[rw][app]=[path]
  param[rw][incubation_temperature]=37
  repo[ro][spec]=[path]
  file[ro][description]=[path]
  model[ro][modernbert_large_nli]=[path]
  data[ro][train]=[path]
  output[model]=[path]
which the rule reads as request.user:
{"repo":   {"rw": {"app": …}, "ro": {"spec": …}},
 "param":  {"rw": {"incubation_temperature": 37}},
 "file":   {"ro": {"description": …}},
 "model":  {"ro": {"modernbert_large_nli": …}},
 "data":   {"ro": {"train": …}},
 "output": {"model": …}}
The kind comes first (repo, file, dir, model, data, param, output), then rw or ro where the kind has both. An output has no split. Proposed; to be settled with dk0.
Too large for git: a model or dataset is named by where it lives and pinned to a version or checksum: a Hugging Face model and revision, a web address with its sha256, an object-storage path with its version, or an MLflow registered model version. Each executor downloads it once into a cache and reuses it. A version of the project records the pin, not the bytes. An output, such as trained weights, is saved to the artifact store you choose (the project folder, object storage or MLflow), and each version records its checksum.

Set up (optional)
A function rule run once per executor before the first experiment, to download or prepare inputs. Given the same items as the experiment. The only step that may use the internet and the setup secrets.
Run the experiment
Runs at every version the mecha tests: trains, builds or runs the program, then measures each case. It is given the items above as parameters and returns, for each case, whether it passed and the value of each outcome named in section 2.
Grade out of sight (optional)
For hidden answers: a separate function rule, run apart from the experiment with only the hidden data and the experiment's output. It returns the result per case, never the answers or a score the mecha could tune against.

2. What counts as a better result
The outcomes the experiment reports for each case, and which way is better. A named value is one the run rule returns by name for every case. The typical range sets the scale for weighing: a result at the start of the range counts 0 and one at the end counts 1, and results outside the range still count, below 0 or above 1. A change worse than "Never adopt if worse than" is never adopted, however good its other outcomes.

3. Revelations
Established findings and constraints you hold as true. At IDEATE the mecha proposes new hypotheses that apply them, alongside hypotheses drawn from the results so far. At DROP it drops a new hypothesis that clearly contradicts one, and flags and believes less one that may. The LLM reads them ahead of its own analysis whenever it proposes a hypothesis or writes an experiment. A new revelation is checked against the others before it is added.
